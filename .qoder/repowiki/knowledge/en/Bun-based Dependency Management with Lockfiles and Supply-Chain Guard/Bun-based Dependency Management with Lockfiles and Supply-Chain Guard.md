This repository manages dependencies through Bun as the primary package manager, with npm lockfile artifacts also present for compatibility.

**System and tools**
- Package manager: Bun (declared via `packageManager: "bun@1.3.14"` in `package.json`).
- Lockfiles: both `bun.lock` (Bun's native lockfile) and `package-lock.json` (npm v3 lockfile) are committed to the repo, ensuring deterministic installs across environments.
- Configuration: `.npmrc` sets `legacy-peer-deps=true`, relaxing peer dependency resolution; `bunfig.toml` configures install behavior.

**Declaration and versioning**
- All runtime and development dependencies are declared in `package.json` under `dependencies` and `devDependencies` using caret (`^`) ranges, allowing minor/patch updates while pinning major versions.
- No workspace or local `file:`/`link:` dependencies are used — all packages are resolved from the public registry.
- The project is marked `private: true`, so it is not published as a package itself.

**Lockfile strategy**
- `bun.lock` is the authoritative lockfile generated by Bun and contains exact resolved versions and checksums for every transitive dependency.
- `package-lock.json` (lockfileVersion 3) is also committed, likely for CI/tooling that expects an npm-style lockfile.
- `bunfig.toml` enables `saveTextLockfile = true`, ensuring the lockfile stays in sync with `package.json` changes.

**Supply-chain and update policy**
- A 24-hour minimum release age guard is enforced (`minimumReleaseAge = 86400` seconds), preventing installation of packages published within the last day.
- Specific `@lovable.dev/*` packages are excluded from this guard via `minimumReleaseAgeExcludes`, acknowledging their rapid iteration cycle.
- Any bypass of the guard requires explicit user confirmation before adding new entries.

**Peer dependencies**
- Peer dependency conflicts are tolerated via `legacy-peer-deps=true` in `.npmrc`, avoiding install failures when peer mismatches occur between tightly coupled libraries (e.g., React + Radix UI + shadcn/ui components).

**No vendoring**
- There is no `node_modules` directory committed, nor any vendoring strategy — dependencies are installed fresh at build time from the registry using the lockfiles.
